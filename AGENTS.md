# AGENTS.md

This file provides guidance to the AI agent when working with code in this repository.

## Build & Run

```bash
cd src && bash compile.sh        # builds ./src/n_queens
./src/n_queens <N> [preset_queens]   # N in [6,28], preset_queens default 6
```

Compile target is **sm_89** (RTX 4090). Requires `nvcc` with C++17 and `-allow-unsupported-compiler` (needed for newer gcc/nvcc combinations). `--ptxas-options=-v` outputs register/smem stats — use these to verify optimization changes.

## Architecture

This branch (`faf-cuda-reload`) has a **single production kernel — the reload form**:
- **`src/n_queens_cuda.cu`**: faf's D4 constellation tree (4 border queens i,j,k,l + preset queens + per-block `jkl_queens` table) × main's reload state machine — 16B/level `int4` full-state stack `{cur,left,right,residual}` (slot `e*32+l`, zero bank conflict), per-trip reload, **no** capture bits / anti-revisit mask; leaf counting via `__popc(child)` at row N-2 (second-to-last-row optimization); manual unroll×8 (#70, safe because the #69 guard body is idempotent); exact-depth dynamic shared memory.
- **Hot loop (#68)**: the stack is **depth-indexed** (slot index = path depth; no pop+push compaction), so the jkl row is `start + top` and the state `LDS.128` and the jkl `LDS` issue back-to-back and independently — no POPC in the loop (SASS confirmed; measured −4.8%/−3.0%/−2.6% at N=20/21/22). The compaction's saved iteration is replaced by a **return-slot encoding** packed into the free high bits of `cur` (5 bits for N≤27; N=28 uses 4 bits of `cur` + bit 28 of `right`): each state stores the `top` to restore on pop, push does `ret' = exhausted ? ret : top`, pop does `top = ret` (one op fewer than the earlier skip-count version, #69: −4.9%/−3.2%/−2.9% at N=20/21/22). `col` is masked to N bits at task setup to free those bits. Any change that reintroduces compaction breaks the row=start+top invariant. The guard body is **idempotent** (its ret=0 keeps top at 0), which is what allows the loop to be **unrolled x8 with no mid-loop top check** (#70: −3.5%/−7.2%/−8.3% at N=20/21/22; x16 is 0.5% worse). Stack accesses in the hot body use **byte offsets** (`sp + top*512`, `sp = (char*)stk + sbase*16`), so the state load address is 1 IMAD + a scaled `[R.X16+…]` address mode (registers 56→54; #71: −2.0%/−0.6% at N=21/22, neutral at N=20). The current level needs only one address register: the residual store is `cslot+12` and the push is `cslot+512` (an immediate offset, `STS.128 [R+0x250]`); the next top is selected before packing (`push = (top != leaf_top) && (child != 0)`, `ntop = push ? top+1 : (exhausted ? retplus : top)`), which removes the separate predicated push-address IMAD and the predicated top update (SASS window 25→23; #72: −0.6% at N=20/21, counts exact). The right-diagonal update is a plain `(right|p) >> 1` (SASS `SHF`, ALU pipe), **not** `__umulhi`: after #67–#72 the multiplier/IMAD pipe is the scarcer resource, so the #59 trick was reverted (#73: −0.6%/−0.9%/−2.6% at N=20/21/22, counts exact).
- **Preemptible scheduling (#56, production)**: each block owns `block_size*K` same-jkl constellations held in a per-block global-memory FIFO queue; every round each lane pops a task, runs a `slice`-iteration budget, then checkpoints `{stack, partial solutions, top}` to global memory and re-enqueues (two `__syncthreads()` per round). The smem layout/occupancy are unchanged. Kernel args: `K`, `slice`, `ckpt/ckpt_top/ckpt_sol/queue`. Defaults: **K=16 for preset≥7 (K=6 for r6), slice=16384** (`NQ_K`, `NQ_SLICE` override; #63).
- All N=6–28 dispatch to the reload kernel via a `switch` in `cuda_solve()`; block size comes from a **per-N/preset table driven by the real occupancy** (#66/#71): 20→128, 21→32 (r6) / 128 (r7), 22→64, 23→64 (r7) / 32 (r6), 24→32, 25–26→96 (r7, 3-warp blocks = 9 warps; #67), 27→32, 28→64 (r7) / 128 (r6), else 64 (`NQ_BLOCK` overrides for sweeps). Each block covers `block_size*K` constellations of one jkl group (`K` = queue pool depth per lane; default **16 for preset≥7, 6 for r6**, #63; padding aligns to `block_size*K`). Multi-GPU: blocks are assigned to GPUs by `blk % gpu_num` (mod-interleaved, `solve_multi_gpu()`).
- Elsewhere: the original **capture** kernel (4B/level stack + `ld_mem`/`rd_mem` + funnelshift + `direction` trick) is frozen on branch `faf-cuda`; the int4+PTX legacy solver lives on `main` (`gpu_solver.cpp`).

`constellation.cpp` implements D4 symmetry enumeration (rotation/mirror elimination, `symmetry()` returns multiplier 8/4/2). Kernels are **template-instantiated per N** (6–28).

## Critical Performance Knowledge

- The kernel family is **latency/pipe-bound at the production occupancies**: measured at N=21, 10→9/8/7 warps costs +8.0%/+17.5%/+30.8% (#60), i.e. each resident warp is worth ~6–10% until the ALU pipe saturates. Occupancy is smem-limited (see the real 1KB/block-overhead ladder below), so more warps require less smem per warp — but any hot-loop mode switching to achieve that is fatal (#60).
- **Optimization is a sponge (#72 lesson):** never declare a hard floor from the source structure alone. After #70/#71 the body looked minimal (25–27 SASS, fully if-converted, ~90% smem bandwidth at 12 warps), yet one more SASS pass found two equivalent rewrites (push store as an immediate offset from the current slot address; next top selected before packing) worth −0.6% at N=20/21. Re-dump SASS after every accepted change; hunt specifically for redundant address materialization (`IMAD`/`LEA` per body), predicated top/ret updates that can become one select, and duplicate base registers. Validate sub-1% effects with a same-session **interleaved A/B** (single runs drift 1–3% with clock/power state); trust only the per-round ordering.
- **ptxas canonicalizes integer arithmetic (#74 lesson):** `<<1`, `start+top` and `residual-p` are always lowered to the FMA/multiplier pipe (`IMAD.SHL`/`IMAD.IADD`); inline `shl.b32`/`add.s32`/`sub.s32` and the `lt+lt` form produce **byte-identical SASS**, so the left shift, the jrow add and the residual subtract cannot be moved to the ALU from the source. Only an intrinsic like `__umulhi` forces `IMAD.HI`; removing it (#73) moved the right shift to `SHF` and gained 2.6% at N=22. The one remaining movable op, `residual ^= p` (LOP3/ALU, instruction-neutral), is 1.3% slower at N=22. **Corollary: if a source rewrite leaves SASS unchanged, it cannot change performance — verify codegen before spending timing runs.**
- **Measured ceiling (#71, instrumented body count + SASS):** N=20 r7 executes 727.9G lane-bodies in 1.035s on a 4090 = 0.069 warp-bodies/cycle/SM at 12 warps; with ~13 shared-memory wavefronts/body that is ~0.9 wavefronts/cycle/SM, i.e. **the smem pipe is ~90% saturated at 12 warps**. At 9 warps (N=26 r7) the kernel is slightly latency-bound (~2%/warp). The unrolled body is a flat, fully if-converted 25–27 SASS sequence (no BSSY/BSYNC). 12 warps at N=26 would need 16 stack levels vs the actual 21 — unreachable, so **remaining headroom at N=26–28 is ~5% total**. Refuted again at #71: whole-16B residual write-back (+2.6%), group-level 32-bit solution accumulator (neutral), XOR/predicate zero-test fusion (neutral), >2-row leaf and register-carry (SIMT nested-path tax).
- The reload kernel's per-trip full-state reload **is** the optimal form — register-carried / delta-stack variants were refuted five times (warp-divergence tax; the compiler schedules the plain unconditional-reload loop better).
- Reload vs capture (same-session A/B): −12…−13% at N=19–21, −8.1% at N=22 (149.1s vs 162.2s), −8.0% at N=23 (1352.4s vs 1469.7s). κ model: reload ≈ 3.6–4.0× per-warp throughput; flip points are ruled by per-block smem → resident blocks → resident warps.
- **Preset selection with the preemptible kernel (#62): r6 for N=20/21 (host-bound) and r7 for N≥22.** On 8×4090 r7 is 16–35% faster than r6 at N=22–25 because r6's 8–10× larger tasks amplify the queue's pool-drain tail (N=25: r7 11,948s vs r6 13,332s, #65); the old residency-ladder pick (“6 at N=25/27, 7 at N=24/26/28”) is obsolete. r8's kernel is another ~7% faster but its host pipeline/memory explode (~1.3B constellations at N=26 → ~42GB host + ~21GB GPU constant array). Real occupancy for sizing: `warps/SM = floor(101376 / (wpb*levels*512 + 1024)) * wpb` with ~1KB fixed per-block overhead and ~99KB usable (levels = N−4 for r6 / N−5 for r7, guard included; wpb = block warps), #60/#66 — validated by the N=23 r7 b=64 gain (9→10 warps, −7.0% at N=23 on 8×5090). N=6/7 require preset ≤ N−2.
- **Warp lane-tail waste (1.52× at N=20) was the biggest single-GPU loss and is now captured.** A warp runs until its slowest lane finishes. Oracle reordering by true iteration counts gives −32.1% (#55); the production preemptible scheduler (#56) + ALU work (#59) gives **N=20 1938.8→1428.6ms (−26.3%), N=21 15843→12459.9ms (−21.3%), N=22 145957→108258ms (−25.8%), N=23 1352.4s→981.8s (−27.4%)**, all counts exact; on 8×4090 r7 the combined gain is a uniform −32…−39% at N=20–25 (N=25: 18,384→11,948s), which puts the 8×5090 N=26 r7 estimate at **~25h** at the main-branch 0.775 ratio (#62/#63); the 5090 was **measured** at 8×5090/8×4090 = 0.785–0.845 (#66; sm_120 has the same **100KB usable smem/SM**, 170 SMs, cc 12.0 — the docs' 128KB is the L1/shared total), giving **N=26 26.4–29.7h, N=27 12–13.6d, N=28 126–142d** at ~$100/day (over the $10k budget; needs chunking+spot or cheaper $/work) (f≈0.74–0.79; do not assume larger blocks win on equal warps — b=64 at N=23 was 17.5% slower due to the smem allocation granularity) — within ~5% of the oracle. Coarse dynamic fetch / K-per-thread without preemption does not help (SIMT lockstep at task boundaries); the fine-grained slice+checkpoint version does.
- Occupancy is the remaining lever (~+8%/warp near 10 warps, #60), but any hot-loop mode switching is fatal: a shallow-stack spill (mode base + rare boundary copies) was 2.2x slower even with the spill disabled, and up to 14x with it enabled. Depth-class kernel splits do not help (start=3 constellations carry 87% of the work).
- **Chunk granularity is a speed parameter, not just a fault-tolerance knob.** A GPU holds ~384 blocks (3/SM at N=28 b=64); a job needs ≥4–5 waves or its wall time is set by the single heaviest block (block work is heavy-tailed). N=22 part0 on one 4090: 1/2/4/8/16 contiguous chunks = 18.1/19.6/22.3/28.7/38.6 s (16 chunks = 2.13x). For N=28 use CHUNKS≤4, or `NQ_CHUNK_SPAN` to merge `[chunk, chunk+span)` (e.g. keep a finished chunk0 and run the rest as four spans); `distribute/run_span.sh` implements resume/overlap/zero checks and `summarize.sh` takes `GRIDS=16,16,16,2` for mixed per-part grids. Do not run 16 chunks on a multi-week campaign.
- `print_with_time` flushes stdout, so `distribute/watch.sh` can read the start time/block count from a live log (the kernel itself prints nothing until it finishes).
- Analysis tools: `NQ_DUMP=<path>` dumps per-constellation solutions (`.bin`), ijkl (`.bin.ijkl`) and iteration counts (`.bin.iters`, needs `-DNQ_COUNT_ITERS` in the kernel).
- See `OPTIMIZATION_LOG.md` and `优化日志.md` for the full attempt record (#1–#70).

## Branch Strategy

- `main`: fastest original solver (int4 + PTX, ~3.6s for N=20)
- `faf-opencl`: Step 1 — minimal C/C++ port of NQueensFAF's OpenCL code
- `faf-cuda`: Step 2 — original faf **capture** CUDA port (frozen reference implementation)
- `faf-cuda-reload` (**this branch**): reload-only production line — the 2026-10 optimization campaign (per-N block-size table, exact-depth stack, unroll×2)
- `v4-mid-block` and others: experiment archive (`v4-mid-block` carries the full 39-commit campaign incl. refuted ideas; `faf-reload-loop` is a redundant ancestor of it)

## Gotchas

- Stack layout: lane `l`'s level `e` sits at `sbase + e*32` with `sbase = (lid>>5)*(S*32) + (lid&31)` — never break the stride-32 (bank conflicts).
- Hot-loop codegen: any inner loop or multi-way if/else in the DFS body makes nvcc emit branches + BSSY/BSYNC instead of predication (33→56 SASS/iteration) and costs +33–48% even when it does less work (#55). Keep the body flat and single-path.
- Do **not** re-add `__launch_bounds__(MAX_BLOCK, minBlocks)` with a high minBlocks: 12 blocks/SM caps registers at 42 and forces per-iteration rematerialization of the lane/warp base (loop 33→39 SASS, +16%). Occupancy here is smem-bound; without minBlocks the kernel uses ~55 regs and 33.5 SASS/iteration (#56).
- Queue protocol invariants: all lanes of a block must execute the same number of `__syncthreads()` (the loop exits uniformly when `qtail-qhead==0`); the pool depth is `block_size*K` and must stay ≫ lanes or late-run lanes starve (K=4–6 measured). Checkpoint memory is `cnt*maxd*16B`: at N=26 r7 (~150M constellations) that is **~6.3GB per GPU on 8 cards but ~50GB single-GPU — single-GPU N≥26 does not fit a 24GB card**; host-side constellation arrays are ~5–7GB at N=26.
- **Queue counters must stay 64-bit.** `qhead/qtail/qpop` grow by one per lane per `slice` re-enqueue, i.e. about `nodes_block/slice` per block (~1e9 for an N=28 block). The original 32-bit `int` counters wrapped after ~7h and produced an illegal memory access in the N=28 campaign (part1/part2 chunk0, 2026-10-25; part0 survived only because its blocks were lighter). The per-block queue is now `2*cap` ints + 24B counters (stride `2*cap+8`); ring indices are `unsigned long long`/`size_t`. Do not shrink the stride back.
- **A CUDA error must never write `.done`.** Launch-configuration errors are not sticky, so `cudaDeviceSynchronize()` alone misses them: every `LAUNCH_N` records `cudaGetLastError()` in `launch_err`; `solve_multi_gpu` sets a shared `had_error`; `cuda_solve()` returns -1 and `main` returns 1. `run_part.sh` also treats a zero partial sum as a failed chunk and re-runs a stale zero `.done`.
- N=24–28 production config (reload @ block size 32) was κ-model projected; block=32 is **validated at N=24 on 8×4090**, and with the queue kernel **r7 beats r6 by 21–22% at N=23/24** (#62). N=25–28 still projected.
- Capture-kernel traps — `__funnelshift_l(lo, hi, s)` argument order; anti-revisit mask `free &= ~(queen + direction - 1)` — apply only on `faf-cuda`.
- NQueensFAF reference project is at `../NQueensFAF/` (OpenCL baseline). `tools/nqueens_replica.py` is the per-frame Python oracle used to validate kernel semantics.
